# RecipeWeave Dev frontend

食材を選んで8品のサンプル料理を探し、レシートから冷蔵庫へ登録し、献立・買い物・調理まで操作できるSvelte 5 / TypeScriptのSPAです。GitHub Pagesへの静的配布を想定し、画面遷移はhash routeを使います。

## 起動と検査

Node.js 24を使用します。依存は`npm ci`で固定して導入します。

```sh
npm run check
npm test
npm run build
npm run dev
```

`npm run build`は日本語OCRのworker・WASM・言語データをnpm依存から`public/ocr`へコピーし、サービス文書を`public/help`へ生成してからViteでビルドします。生成先と`dist`はGit管理対象外です。Pagesの配布サブパスは`VITE_BASE_PATH`で指定できます。既定の`./`では同じ成果物をサブディレクトリに配置できます。

## 提供する範囲

- ホームの写真カードは全体を選択でき、未選択も空のチェックを表示します。検索条件に人数・分量はありません。
- 料理詳細の人数・材料別分量は下書きとして保存し、献立・調理へ引き継ぎます。
- レシートはJPEG・PNG・WebP、1枚10MBまで。MIME・シグネチャ・デコード・画素数を検証し、Tesseract.jsで端末内OCRを行います。元画像や読取全文をサーバーに送信しません。
- OCR候補は全行で修正できます。食品の誤除外は戻せます。新しい食材名も登録確定まで一時メモリに置きます。
- 登録は明示確認後に一括反映し、重複疑いは履歴を見たうえで判断できます。取消はその登録の未消費残量だけを対象にします。
- 調理の再開、工程戻り、4種類の図と文章による切り方ガイド、終了時刻を保持するタイマーを提供します。画面外の音通知とガイド動画は未提供です。
- 在庫減算は完了画面の初期OFFのチェックで選びます。数量不明や換算不能な在庫は推測して減らしません。
- 保存先はこのブラウザのlocalStorageです。Web Locksで書込を排他し、同じタブ内の書込も直列化します。非対応環境では保存操作をエラーとして示します。
- JSONバックアップを検証して確認後に全置換できます。壊れた保存データの復旧にも明示確認と変更競合の検査を必要とします。
- AWSの認証・端末間同期はこのDevでは未提供です。

## 検証の区別

`src/lib/domain.test.ts`は数量計算・在庫・重複・取消・バックアップの境界を検証します。`src/App.test.ts`はSvelteをjsdomへ実際にmountし、ボタン・入力・非同期保存を通じて利用者の操作を検証する**simulated DOM統合テスト**です。Tesseractをモックした成功を実画像の読取成功として扱いません。

ローカル環境では実ブラウザのアクセス制約があったため、実ブラウザでの描画・カメラ・タッチ・OCR worker・画面外動作を手動検証したとは記録していません。公開Pagesでの確認結果はプロジェクトの受入記録を参照してください。エージェントによるコード・文書レビューも、実利用者テストとは区別します。

正本は`../spec/requirements/requirements.qnt`、利用者向け説明は`../docs/service/`です。画像内の文言より、この正本と確定したマニュアルの操作名を優先します。

日本語OCRの局所確認として`node scripts/ocr-smoke.mjs`を実行し、既存の生成UI画像`22-receipt-upload.png`から195文字（日本語77文字）を認識しました。同じTesseract 7・日本語モデル・WASMのNode側の組合せを確認した結果であり、ブラウザworkerや実レシートの認識精度を合格としたものではありません。全文・元画像はこのスモークの出力へ保存しません。
