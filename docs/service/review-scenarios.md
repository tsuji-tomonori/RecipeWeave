# RecipeWeave 利用者レビュー用シナリオ

この文書はマニュアルとQ&Aを使った仮想レビューの入力で、実施結果そのものではありません。文書の独立第2回レビュー結果は `reviews/novice-review.md` と `reviews/receipt-review.md` に記録しています。この一覧は正規化DB・認証API版へ更新しています。上記の過去レビューは旧版時点の記録であり、現在版の受入完了を示しません。エージェントが説明を読んで到達できても、実機での使いやすさや利用者の継続利用を証明したことにはしません。

## 評価の進め方

1. レビュアーにはサービス概要、マニュアル、Q&A、生成画像を渡す。
2. 下の課題について「どこを押すか」「何が変わるか」「間違えたときどこへ戻るか」を、資料だけを根拠に答えてもらう。
3. 資料にない操作を想像して補った回答は未解決として記録する。
4. 課題の成功だけでなく、何の手間が減ったか、使わない理由が残るかを記録する。
5. 指摘ごとに資料を直し、修正箇所と関係する別の課題を再確認する。

## レビュー記録様式

| 項目 | 記録内容 |
|---|---|
| 実施者／役割 | 初めて使う人、買い物後の登録者、調理中の利用者など |
| 対象資料 | 版・画像名・確認日 |
| シナリオID | U01〜U24 |
| 読めた操作 | 押す対象と順番を資料の文言で記録 |
| 不明点 | 操作・結果・失敗復帰で不足した説明 |
| 価値の評価 | 減った手間、残る手間、使わない理由 |
| 判定 | PASS／要修正／実機確認が必要 |
| 修正・再確認 | 変更箇所と再確認結果 |

## 文書レビューを終える条件

- U01〜U24に対して、資料だけから操作・結果・戻り方を説明できる。
- 価格と数量、未確定と0、購入チェックと在庫登録、サンプルと実処理を混同しない。
- 在庫の一括追加・取消・完成時反映が、意図しない二重変更を起こす説明になっていない。
- レビュアー間で異なる操作を想像していた箇所を解消する。
- 未提供機能や未確認事項を完了済みの機能として説明しない。

## 文書レビューだけでは終わらない確認

- 実端末で押しやすいか。画面幅や文字拡大で主ボタンが隠れないか。
- 実レシートの読み取りが役に立ち、手入力より訂正の手間が少ないか。
- 画面を閉じたり通信が失敗したりしても、在庫や調理位置を復帰できるか。
- 生成画像と実画面で、ボタン名や順番が一致しているか。
- 利用者が実際の買い物・料理で継続して使う価値を感じるか。

残った確認は受入記録へ引き継ぎます。エージェントの仮想レビューを実利用者テストと呼び換えません。
